# CLAUDE.md

Chrome MV3 extension ("COMPRAFACIL Scraper") that scrapes Amazon.com, Michael Kors, Sephora, Marc Jacobs and Kate Spade product listings into the COMPRAFACIL scraping template (.xlsx, generated by `xlsx.js` from the bundled `assets/plantilla.xlsx`). There is no build step and no dependencies: plain ES modules loaded "unpacked" from the repo root (where `manifest.json` is). Documentation for humans lives in `docs/` (Spanish): `DESARROLLO.md` (architecture, messages, storage, tests, release), `CONFIGURACION-REMOTA.md` (every `config.json` key), `BACKEND.md` (how the backend reads the Excel), `GUIA-DE-USO.md`, `INSTALACION.md`, `CATEGORIAS.md`, `PENDIENTES.md` (status and open tasks). Version history lives in `CHANGELOG.md`. This file keeps only the rules and pitfalls; read the docs for details.

## Working with the user
- The user (Aldair, COMPRAFACIL) writes in Spanish and is new to Git/GitHub. Reply in Spanish, explain Git steps plainly, and offer to run commands.
- Pattern: the user asks for a change, you implement and verify it, bump the version, then wait for "súbelo"/"publícalo" before pushing or tagging. Pushing to `main` is visible to every installed extension, because config.json and categories.json are served raw from it.
- Before publishing, ask whether there are pending items to include.

## Architecture invariants (details in docs/DESARROLLO.md)
- Layout: `src/background` (service worker), `src/inyectados` (`familias.js`, `lector.js` reads one product, `scraper.js` runs the flow; injected in that order), `src/popup`, `src/preview` (`preview.js` plus `estado.js`, `panel-variantes.js`, `acciones.js`; those modules never import `preview.js`, they get its render functions through `conectar()`), `src/options`, `src/comun` (shared modules; `lectores-variantes.js` reads the other sites' variants for the preview and is never injected), `assets/` (template and icons), `tests/`, `tools/`. Root keeps only `manifest.json`, `config.json`, `config.default.json`, `categories.json` and the top-level docs. Paths for `getURL`/`executeScript` are from the package root; icon paths in code are absolute (`/assets/icons/...`) so they work from any page and in `chrome.action.setIcon`.
- Extractions run in the service worker, never in the popup: the popup sends `{type:'enqueue', job}`; `background.js` keeps `storage.local.jobs` (`actual`, `cola`, `ultimo`), runs one job at a time, injects `familias.js` + `lector.js` + `scraper.js` and calls `globalThis.__cfScraper(siteConfig, opts)` without awaiting. The scraper reports via `scrapeProgress`/`scrapePartial`/`scrapeDone`/`scrapeConfirm`; partial products in `storage.session.parcial` are saved if the tab closes, reloads (watchdog alarm checks `globalThis.__cfCorriendo`) or the user stops (`globalThis.__cfDetener`).
- Prefer modes that work with the tab hidden (fetch, server JSON); a scroll-read mode pauses while `document.hidden`.
- All page-specific selectors live in `config.layouts` (JSON), not in code. `config.pageTypes` reserves layouts for one page type (product page `/dp/` uses only `detalle`, which never runs elsewhere).
- MV3 forbids remote code. Only data is fetched: `config.json` and `categories.json` from raw.githubusercontent.com on `main`. Both must stay at the repo root: installed versions fetch them from a fixed URL.
- `config.sites[]` overrides the root config keys per site. The root keys (Amazon) and the legacy `csv` key stay for installed 1.5.x/1.7.x. List key: the ASIN for Amazon, `site:SKU` for others.
- `categories.js`: GitHub, then cache, then the bundled `categories.json`. The `categorias.yml` workflow logs in with the repo secrets `CF_EMAIL`/`CF_PASSWORD` (JWT, no "Bearer") and commits only when the API data changes.
- Service-worker messages that change the list (`quitarProductos`, `restaurarProductos`, `asignarCategoria`, `limpiarCategoria`, `restaurarCategoria`, `cambiarGuiaTalla`) run under `conLock` (`cambiarLista`), are refused during an `exportar` job and from non-extension senders.
- `filasExcel` (`xlsx.js`) computes each row's values and is shared by `buildWorkbook` and the preview, so the preview always matches the file. `descarga.js` holds "Descargar Excel" for popup and preview (direct, or a queued `exportar` job when families are pending).
- Shared DOM helpers (`$`, `el`, `plural`, `showStatus`) live in `src/comun/dom.js`. `familias.js`, `lector.js` and `scraper.js` are injected classic scripts: they cannot import (`lector.js` shares its `estado` getters and the `fallos`/`excluidos` sets with `scraper.js`).
- Site icons: `config.sites[].icono` (default: the site `id`) picks the bundled `assets/icons/sitios/<icono>-16/32.png` (generated by `tools/iconos-sitios.mjs`). Packaging must include `src/`, `assets/` and the root files except `config.json` (release.yml, empaquetar.ps1); `tests/rutas.test.mjs` checks it.
- `groups.js`: each "Extraer" creates a named group (unique names); the same product re-extracted moves to the latest group; exported in `ref_grupo`. `history.js`: per-user history in `chrome.storage.sync`, one key per page (`h_<fnv-hash>`), capped at 150 entries.

## Product rules
- Amazon: ads skipped (`.AdHolder`, `.puis-sponsored-label-text`); category pages `/b?node=` read from carousels; store pages may carry a `/-/es/` locale prefix; next pages fetched in the background.
- Families (`familias.js` + `config.sites[].familias`): the backend downloads the whole variation family of each Amazon ASIN, so with "Extraer variantes" the extension keeps one ASIN per family (from each `/dp/` page, 1.5–3 s random pause). In products mode the limit counts families and the job asks "Seguir/Detener" (`scrapeConfirm`, no timeout). Unverifiable products keep `Familia sin verificar` in `ref_duplicado`; export re-verifies Amazon products without `familia` as a service-worker job (`tipo: 'exportar'`). Kate Spade families span several styles, so they are always deduped (`familias.tipo: "jsonld"`, `siempre`, `hermanos` stored per product).
- Group options: "Extraer variantes" is on by default except Amazon and Sephora (`SIN_VARIANTES_POR_DEFECTO` in popup.js; unchecking elsewhere asks for inline confirmation). It is fixed per group at extraction (`groups[id].variaciones`) and never editable afterwards, not even in the preview (confirmed by the user). Without it the job runs with `cfg.familias = null` (except `familias.siempre`) and export never dedupes or verifies those products. "Guía de tallas" is on by default and editable per group from the preview (`cambiarGuiaTalla`, which also rewrites the `Variaciones:` summary line). Exported as `variacion`/`guia_talla` = `Sí`/`No`.
- Michael Kors: SKU from the link path `/<ID>.html`; "Load More" chunks fetched in the background (`data-url`, `start += sz` fallback, layout `fetchItem`).
- Sephora: category/brand pages read 60 products per page from `script#linkStore` (`loadMore.json`); search pages scroll the virtualized grid (`loadMore.mode: "scroll"`), detecting the next page by URL change plus new products. Sponsored tiles skipped via `layout.exclude`. Never trust Sephora's canonical/`linkStore`: they go stale on SPA navigation.
- Kate Spade: host `www.katespade.com` only (outlet excluded). Infinite scroll `?page=N`, fetched with `loadMore.pageFetch`; products limit only; lazy tiles take the image from the link.
- Marc Jacobs: on a product page with two models, the open model is taken (`linkChild*`, `data-product-id`).
- A site an older version can't handle safely must extract nothing there (e.g. an `asinFrom` source it doesn't know, like Kate Spade's `linkEstilo`/`urlEstilo`), because `config.sites` is remote. Never remove these compat guards.

## Excel and template
- Bundled `assets/plantilla.xlsx` column order: `ecomerce, sku, variacion, guia_talla, condicion, link, Buscar categoria, codigo_categoria, seguimiento`, then `marca…precio`; `xlsx.js` inserts the `ref_*` columns after `seguimiento` and shifts the rest (cells, widths, sqref).
- Conditional formatting and data validation (red `sku`/`link` when the wrong one is filled or empty) are edited in `xl/worksheets/sheet1.xml` inside `assets/plantilla.xlsx`; `xlsx.js` only shifts and extends the ranges.
- Never build DOM from remote data with innerHTML; use textContent.

## Backend is fixed: the extension adapts to it (details in docs/BACKEND.md)
- Current rule: only Amazon rows carry the `sku` cell, with the `link` cell absent; every other ecommerce carries the `link` cell with the `sku` cell absent, and the bot extracts the SKU from the link (`xlsx.skuOnlyInLink`, `xlsx.linkOmit`). The `ecomerce` cell has no spaces (`MarcJacobs`, `KateSpade`, `MichaelKors`, done in `filasExcel`); the spaced name stays everywhere else.
- The backend reads the first sheet by header name (`XLSX.sheet_to_json`, no options). Never write empty cells (a `''` breaks its `??` fallbacks and an empty `sku` row is silently dropped). Never fill backend columns (`marca`, `nombre`, `precio`, `peso`...): they become fixed values. Helper columns use the `ref_` prefix.
- Sephora links: `skuId` query param only, and the first `-([A-Z]\d+)` of the pathname must be the `-P<digits>` id. One row per `P…` id. Marc Jacobs and Kate Spade: one row per base model/style (colors collapse into one product).
- Do NOT propose changes to the backend code (not even small regex fixes). Work around its quirks inside the extension.

## Adding an ecommerce: required criteria
A new site is held as local commits only (no push to `main`, no tag) until the user confirms a real Chrome test, because a push publishes `config.json` to every installed extension. The version bump happens in the release commit. Each new site must:
1. **Backend first.** Ask how the backend parses it (which link part or column becomes `sku`/`product_id`, what makes the SP drop a row, how it dedupes). Write the answer in docs/BACKEND.md. Adapt the link and the `sku` cell to it.
2. **Saved HTML from real Chrome** (`copy(document.documentElement.outerHTML)`, ad blockers off): product page, sale product, search, category, brand page, plus real URLs (search, filter, page 2). Analyze with jsdom before writing selectors. Keep saved HTML in `tests/html/` (git-ignored: the repo is public) and add it with its tab URL to `tests/casos.json`, so `extraccion.test.mjs` snapshots it (`tests/html/fotos/`; accept intended changes with `ACTUALIZAR_FOTOS=1`). A refactor must pass without touching the snapshots.
3. **Cover the four page types:** product page (`pageTypes`, only that product, with the variant selected at that moment), search, category and brand.
4. **Ads are never extracted.** Skip "Sponsored"/"Patrocinado" tiles with `layout.exclude`; the summary reports how many were skipped.
5. **Pagination up to the user limit** (`loadMore`): pages (default 1, counted from `loadMore.pageParam`, cap `maxPages` 10) or products, one mode at a time, remembered per site in `storage.local.loadPrefs`. No limit field on pages without next pages (`loadMore.urlPattern`). Modes: default click (Load More button, unused today), "scroll" (Sephora search), "fetch" (Amazon, Michael Kors, Kate Spade). Detect a new page by URL change plus new products, never only by "the first item changed".
6. **Never trust SPA leftovers.** Canonical, `<title>` and embedded JSON can belong to the previous page. Prefer the tab URL and DOM attributes of the item.
7. **Link and SKU validation:** build a clean link (only the params the backend needs), check it with the backend's own regex, skip with a warning any product the backend would drop or misread. One row per backend product id.
8. **Regions:** only the US site is extracted. Add a region redirect (`sites[].regions`) only when the user asks.
9. **Older versions** read the same remote `config.sites`: they must extract nothing on a site they can't handle safely.
10. **Tests:** jsdom over every saved HTML, a pagination simulation, the popup with a fake `chrome`, the Excel read back the way the backend reads it, and the previous sites' regression tests. Report what was not tested in real Chrome. Then update `docs/`, README and CHANGELOG.

## Release checklist
1. Bump `manifest.json` version, then in both `config.json` and `config.default.json` set `latestVersion` and increment `revision`. In the same release commit, move the CHANGELOG entry from "en preparación" to its date and update the status at the top of `docs/PENDIENTES.md` ("Publicada: vX.Y.Z"). While a version is in preparation, PENDIENTES keeps saying the previous version is the published one.
2. Commit and push to `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z`. `release.yml` checks that the tag matches the manifest and publishes the zip.
3. Selector or `xlsx.refColumns`-only fixes need no release: edit `config.json`, bump `revision`, push.

## Rules
- The repo is PUBLIC: never commit tokens, passwords, VPS IPs or SSH details. Credentials go in GitHub Secrets.
- UI text and code comments are in Spanish. Keep modules small and dependency-free.
- CSS: `[hidden]{display:none !important}` exists because component `display` rules override the attribute. Keep it.
- Verify before claiming done: `cd tests && npm test` (jsdom and SheetJS are dev-only dependencies there, never packaged), `node --check file.js` (PowerShell has no `<` redirection; without a file node waits on stdin), jsdom simulations with a fake `chrome` for popup flows, and headless Chrome screenshots for UI changes. Tell the user what was NOT tested in real Chrome.
