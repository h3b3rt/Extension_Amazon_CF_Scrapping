# CLAUDE.md

Chrome MV3 extension ("COMPRAFACIL Scraper") that scrapes Amazon.com, Michael Kors, Sephora and Marc Jacobs product listings (Kate Spade pending) into the COMPRAFACIL scraping template (.xlsx, generated by `xlsx.js` from the bundled `plantilla.xlsx`). There is no build step and no dependencies: plain ES modules loaded "unpacked". Documentation for humans lives in `docs/` (Spanish).

## Working with the user
- The user (Aldair, COMPRAFACIL) writes in Spanish and is new to Git/GitHub. Reply in Spanish, explain Git steps plainly, and offer to run commands.
- Pattern: the user asks for a change, you implement and verify it, bump the version, then wait for "súbelo"/"publícalo" before pushing or tagging. Pushing to `main` is visible to every installed extension, because config.json and categories.json are served raw from it.

## Architecture (see docs/DESARROLLO.md)
- Extractions run in the service worker (v1.9.0), never in the popup (a closed popup used to lose the result): the popup sends `{type:'enqueue', job}`; `background.js` keeps `storage.local.jobs` (`actual`, `cola`, `ultimo`), one job at a time, injects `scraper.js` and calls `globalThis.__cfScraper(siteConfig, {pages|limit, jobId})` without awaiting. The scraper reports via `scrapeProgress`/`scrapePartial`/`scrapeDone`; partial products go to `storage.session.parcial` and are saved if the tab closes, the page reloads (watchdog alarm checks `globalThis.__cfCorriendo`) or the user stops (`globalThis.__cfDetener`). `jobs.js` saves list/group (with `resumen` lines shown in the popup's ▸ dropdown)/history; `export.js` builds the Excel from popup or service worker. Notification (`notifications` permission) + badge (`2/5`, `⏸`, `✓`). Prefer modes that work with the tab hidden (fetch, server JSON); a scroll-read mode pauses while `document.hidden`. All page-specific selectors live in `config.layouts` (JSON), not in code.
- MV3 forbids remote code. Only data is fetched: `config.json` (selectors, xlsx output settings, version notice; the legacy `csv` key stays only for installed 1.5.x) and `categories.json`, both from raw.githubusercontent.com on `main`.
- `categories.js`: GitHub, then cache, then the bundled `categories.json`. The `categorias.yml` workflow logs in to the COMPRAFACIL API with the repo secrets `CF_EMAIL`/`CF_PASSWORD` (JWT, no "Bearer") and commits `categories.json` when the data changes. Those secrets are configured (2026-10-01) and the workflow runs fine; it commits only when the API data changes.
- `sites.js` + `config.sites[]`: each site overrides the root config keys (root = Amazon, still read by v1.7.x). Popup/icon title per site; `ecomerce` stored per product; list key is the ASIN for Amazon and `site:SKU` for others. Amazon (v1.9.0): ads skipped (`.AdHolder`, `.puis-sponsored-label-text`), category landing pages `/b?node=` read from carousels (`categoria` layout), store pages may carry a `/-/es/` locale prefix, next pages fetched in the background (`loadMore.mode: "fetch"` in `sites[0]`, default limit 60). Michael Kors takes the SKU from the link path `/<ID>.html` (same rule as the backend's parseMkUrl) and uses "Load More" (each click counts as one page). Michael Kors (v1.9.0) fetches the "Load More" chunks in the background (`data-url` of the button, `start += sz` fallback, layout `fetchItem` for chunk tiles). Sephora category/brand pages read the 60 products per page from the server JSON `script#linkStore` (`loadMore.json`, `?currentPage=N`, no ads in it); search pages have no such data and fall back to the virtualized grid read while scrolling (`loadMore.mode: "scroll"`, then "Show More Products" to `?currentPage=N`, default limit 60; the next page is detected by URL change + new products, never by "first item changed", because Sponsored tiles repeat across pages and the first tiles are never unmounted; Sponsored tiles are skipped via `layout.exclude`), key `sephora:P…`, link built by `config.variant` (`?skuId=` only), `sku` cell omitted (`xlsx.skuOnlyInLink`), other regions get an "open US version" button (`sites[].regions`). Never trust Sephora's canonical/`linkStore`: they go stale on SPA navigation. A new site needs `host_permissions` (release); a site an older version can't handle safely must fail to extract there (e.g. an `asinFrom` source it doesn't know), because `config.sites` is remote.
- Amazon families (v1.10.1, `familias.js` + `config.sites[0].familias`): the backend downloads the whole variation family of each ASIN, so the extension keeps one ASIN per Amazon family (first on the page). The family comes from each `/dp/` page (`parentAsin`, `dimensionToAsinMap`), fetched with a 1.5–3 s random pause; in products mode the limit counts families and the job asks "Seguir/Detener" (`scrapeConfirm`, waits with no timeout). Unverifiable products are kept with `Familia sin verificar` in `ref_duplicado`; export re-verifies Amazon products without `familia` as a service-worker job (`tipo: 'exportar'`) and dedupes by family.
- Group options (v1.10.1): "Extraer variantes" and "Guía de tallas" checkboxes (default off), fixed per group at extraction (`groups[id].variaciones/guiaTalla`, never editable afterwards); exported as `variacion`/`guia_talla` = `Sí`/`No` (old groups: `No`). Without variantes the backend creates only that ASIN, so the job runs with `cfg.familias = null` and export never dedupes or verifies those products. The group summary starts with the options and `Duración` (excludes queue, the Seguir/Detener wait and the hidden-tab pause); the notification shows it too.
- Bundled `plantilla.xlsx` is reordered (v1.10.1): `ecomerce, sku, variacion, guia_talla, condicion, link, Buscar categoria, codigo_categoria, seguimiento`, then `marca…precio`; `xlsx.js` inserts the `ref_*` columns after `seguimiento` and shifts the rest (cells, widths, sqref).
- `config.pageTypes` reserves layouts for one page type (product page `/dp/` uses only `detalle`, which never runs elsewhere).
- `groups.js`: each "Extraer" creates a named group (`storage.local.groups`, product field `grupo`); names are unique; same ASIN re-extracted moves to the latest group; exported in `ref_grupo`.
- `history.js`: per-user history in `chrome.storage.sync`, one key per page (`h_<fnv-hash>`), capped at 150 entries.
- Never build DOM from remote data with innerHTML; use textContent.
- Backend upload (`XLSX.sheet_to_json`, no options) reads the first sheet by header name. Never write empty cells (a `''` breaks its `??` fallbacks and an empty `sku` row is silently dropped). Never fill backend columns (`marca`, `nombre`, `precio`, `peso`...): they become fixed values. Helper columns use the `ref_` prefix.

## Backend is fixed: the extension adapts to it
- Do NOT propose changes to the backend code (not even small regex fixes). The relationship is one-way: build around the backend's current behavior and work around its quirks inside the extension.
- Sephora (`parseSephoraUrl`): SKU = `skuId` query param of the link; `product_id` = first `-([A-Z]\d+)` in the pathname (meant to be `P123456`; a slug like `-v2-` before it would be taken instead, so the extension must only send links whose first match is the `-P<digits>` id). Leave the `sku` cell absent (a filled `sku` overwrites `product_id`; a `''` drops the row). A link without `skuId` is silently dropped by the SP. Dedupe by `P…` id, one row per product with the listing's default `skuId`. The SP dedupes only by sku, so two skuIds of one product create two products. `variacion`/`color`/`talla` may stay empty (= Simple); `tipo_sku` is not read.
- Marc Jacobs and Kate Spade (`product.controller.ts`): the link is ignored; everything comes from the `sku` cell, which must always be filled. `normalizeSku`: non-string gives null, else trim, cut at the first `-`, uppercase, drop non `A-Z0-9`. The result goes to `sku`, `product_id`, `asin` (Kate Spade: `asin = null`), `variant_id`, `parent_sku`, `base_sku`. Silent drops: empty/absent/`''` sku, sku written as a number (write it as text, `inlineStr`), value that normalizes to `''` (starts with `-`, only symbols), sku already in `productos.sku`/`alt_sku` (insert only), repeated row in the file (SP dedupes by `LOWER(TRIM(sku))`, kept row undefined). `product_id` is VARCHAR(15): a longer sku may break the whole batch (unverified), so skip it. Colors of one style (`H001M01SP21-001`, `-650`) collapse into one product: dedupe in the extension by the normalized base style.

## Adding an ecommerce: required criteria (apply to every new site)
The template accepts Amazon, Sephora, Marc Jacobs, Kate Spade and Michael Kors. v1.9.0 was published on 2026-10-02 with Sephora (plus the Amazon/Michael Kors upgrades), v1.10.0 the same day with Marc Jacobs, and v1.10.1 on 2026-10-03 (Amazon families, group options, column order, duration). Kate Spade goes into v1.11.0, held (local commits only: no push to `main`, no tag) until ready, because a push publishes `config.json` (with the new `latestVersion`) to every installed extension. So the version bump to 1.11.0 in `manifest.json`/`config*.json` happens in the release commit, not before. Each new site must meet the same bar as Sephora before it counts as done:
1. **Backend first.** Ask how the backend parses that ecommerce (e.g. `parseMkUrl`, `parseSephoraUrl`): which part of the link or which column becomes `sku`/`product_id`, what makes the SP drop a row, and how it dedupes. Write the answer in the "Backend is fixed" section. Do not suggest backend changes; adapt the link and the `sku` cell (`xlsx.skuOnlyInLink`) to it.
2. **Saved HTML from real Chrome**, taken with `copy(document.documentElement.outerHTML)` and with ad blockers off (Brave Shields hide Amazon's ads): a product page, a sale product, a search, a category, a brand or sub-brand page, plus real URLs (search, filter, page 2). Analyze them with jsdom before writing selectors.
3. **Cover the four page types:** product page (`pageTypes`, only that product, with the variant selected at that moment), search, category and brand. Each one is checked against its saved HTML.
4. **Ads are never extracted.** Look for "Sponsored"/"Patrocinado" tiles inside the grid and skip them with `layout.exclude` (`self` and/or `selector` + `text`). The summary reports how many were skipped.
5. **Pagination up to the user limit** (`loadMore`). The limit is either pages (default: 1 = only the open page; counted from the page in the URL via `loadMore.pageParam`, which the popup shows as "Páginas a extraer: N a M"; cap `maxPages` 10) or products, one mode at a time, both remembered per site in `storage.local.loadPrefs`. Listing pages without next pages get no limit field (`loadMore.urlPattern`). Modes: `mode` "click" (Load More, Michael Kors), "scroll" (virtualized grid plus a next-page button that changes the URL without reloading, Sephora) or "fetch" (next page is a full reload: fetch it in the background and parse it, Amazon). Detect a new page by URL change plus new products, never by "the first item changed".
6. **Never trust SPA leftovers.** Canonical, `<title>` and embedded JSON can belong to the previous page after client-side navigation. Prefer the tab URL and DOM attributes of the item.
7. **Link and SKU validation in the extension:** build a clean link (only the params the backend needs), check it with the backend's own regex, and skip with a warning any product the backend would drop or misread. One row per backend product id.
8. **Regions:** only the US site is extracted. A region redirect (`sites[].regions`) is added only when the user asks for it (Sephora and Marc Jacobs yes, Marc Jacobs to `homeUrl` `/us-en/homepage` via `regions.otherPath`; Amazon and Michael Kors no).
9. **Older versions** read the same remote `config.sites`: a site an older version cannot handle safely must extract nothing there (for example by using an `asinFrom` source it doesn't know).
10. **Tests:** jsdom runs over every saved HTML, a simulation of the pagination mode, the popup with a fake `chrome`, the Excel read back the way the backend reads it (no `''` cells, no backend columns filled, `sku` present or absent as the backend expects), and the previous sites' regression tests. Report what was not tested in real Chrome. Then update `docs/` (GUIA-DE-USO, CONFIGURACION-REMOTA, INSTALACION, PENDIENTES) and README.

## Release checklist
1. Bump `manifest.json` version, then in both `config.json` and `config.default.json` set `latestVersion` and increment `revision`. In the same release commit, update the status at the top of `docs/PENDIENTES.md` ("Publicada: vX.Y.Z", remove it from "En preparación"). While a version is in preparation, PENDIENTES must keep saying the previous version is the published one.
2. Commit and push to `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z`. `release.yml` checks that the tag matches the manifest and publishes the zip.
3. Selector or `xlsx.refColumns`-only fixes need no release: edit `config.json`, bump `revision`, push.

## Rules
- The repo is PUBLIC: never commit tokens, passwords, VPS IPs or SSH details. Credentials go in GitHub Secrets.
- UI text and code comments are in Spanish. Keep modules small and dependency-free.
- CSS: `[hidden]{display:none !important}` exists because component `display` rules override the attribute. Keep it.
- Verify before claiming done: `node --check file.js` (PowerShell has no `<` redirection; without a file node waits on stdin), jsdom simulations with a fake `chrome` for popup flows, and headless Chrome screenshots for UI changes. Tell the user what was NOT tested in real Chrome.
